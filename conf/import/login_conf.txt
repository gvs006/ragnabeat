// HISTORICO
//
// De 08 a 10/ago/2026 este arquivo trazia "use_web_auth_token: no". O login
// travava em "Please wait" porque o cliente busca o token via HTTP no
// web-server, e a porta 8888 do host estava ocupada pelo OpenTelemetry
// Collector - o rAthena foi publicado na 8889 e o cliente nao sabe disso.
//
// Em 10/ago/2026 o coletor foi movido para a 8890 (as metricas internas dele),
// a 8888 voltou a ser do rAthena, e o token foi religado. O desligamento
// custava caro: sem ele o cliente nao chama /charconfig/save, /userconfig/save
// nem /emblem/upload, entao emblema de guilda e preferencias de UI nao
// funcionavam.
//
// Se o login voltar a travar em "Please wait", confirme nesta ordem:
//   1. a 8888 do host esta livre para o Docker
//   2. o compose publica "8888:8888"
//   3. as tabelas de sql-files/web.sql existem no banco
// Detalhes em docs/auth-token.md.

// REVERTIDO em 10/ago/2026, mesmo dia.
//
// Religar o token trouxe o "Please wait" de volta. Medido: o servidor aceita o
// login e gera o token (teste com pacote CA_LOGIN cru devolveu AC_ACCEPT_LOGIN
// 0x0AC4, e o token foi gravado no banco), mas o cliente TRAVA depois disso - o
// web-server nao registrou uma unica requisicao vinda dele, so o curl de teste.
//
// Ou seja, liberar a 8888 nao bastou. Falta descobrir para onde o cliente
// realmente tenta ir ao buscar o token. O que ja foi eliminado: porta ocupada
// (8888 esta livre e nossa), tabelas ausentes (web.sql carregado), servidor fora
// do ar (os quatro rodando).
